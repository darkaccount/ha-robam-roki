# ROBAM / ROKI 老板电器 Home Assistant 集成

[![Validate & Test](https://github.com/darkaccount/ha-robam-roki/actions/workflows/validate.yml/badge.svg)](https://github.com/darkaccount/ha-robam-roki/actions/workflows/validate.yml)

把老板电器（ROBAM / ROKI）账号下的智能厨电接进 Home Assistant。走云端 REST / MQTT 双通道，状态秒级同步；油烟机可完整控制，其它品类先只读接入，再按设备逐个用「学习模式」补上控制。

本项目是社区**非官方**集成，与老板电器无隶属关系。

## 支持范围

| 品类 | dc | 型号（dt） | 目前支持 |
| :--- | :--- | :--- | :--- |
| 油烟机 | RYYJ | R8229、R9700、R66A2、R5610、R8700、82-I1 等 | **完整控制**：开关、档位、灯光、延时倒计时（到点由集成补发关机）。R8229 已真机验证 |
| 灶具 | RRQZ | 见内置 profile | 只读遥测（左右灶头火力 / 剩余时间 / 工作状态 / 报警） |
| 洗碗机 | RXWJ | 见内置 profile | 只读遥测（工作状态 / 剩余时间 / 门 / 缺盐 / 缺亮碟剂） |
| 净水器 | RJSQ | 见内置 profile | 只读遥测（进出水 TDS / 滤芯寿命 / 制水中 / 漏水） |
| 蒸箱、蒸烤一体机、烤箱、微波炉、消毒柜 | RZQL、RZKY、RDKX、RWBL、RXDG | 常见型号 | 只读遥测（工作状态 / 温度 / 剩余时间 / 门 / 报警） |
| 其它品类 | 任意 | 任意 | 原始属性诊断实体；profile 里声明了 `controls` 的设备还会生成 button 实体 |

> 上表随贡献更新；你补的 profile 通过 review 后，维护者会在这里加一行。没列出的设备也能接入——先只读，再用下面的「学习模式」把控制补上。

### 油烟机档位表

| 型号 | 物理档位阶梯 | HA 滑块对应 | 状态 |
| :--- | :--- | :--- | :--- |
| **R8229 / R9700** | 1, 2, 3, 6（弱/中/强/爆炒） | 25% / 50% / 75% / 100% | 阶梯来自 App / 面板确认 |
| **R66A2 / 66A2H / R8700** | 2, 6（常规/爆炒） | 50% / 100% | 待验证 |
| **R5610** | 1, 6（低/高） | 50% / 100% | 待验证 |
| **未列出机型** | 选项里自定义，或按 1..N 线性 | 自动 | 回退 |

> R8229 / R9700 等的档位阶梯取自官方 App 的控制界面，R8229 另有机主对面板四档的确认。其中部分档位还没有在设备回帧（131 上报）中观测到，仍需 `watch --levels` 取证。

机型不在表里时，在集成**选项 → 常规设置 → 档位列表**里填逗号分隔的档位（例如 `1,2,3,6`）即可。

## 安装

需要 Home Assistant 2024.11.0 或更新版本。

### HACS（推荐）

1. 打开 Home Assistant 的 **HACS → 集成**。
2. 右上角菜单 → **自定义存储库 (Custom repositories)**。
3. 存储库填 `https://github.com/darkaccount/ha-robam-roki`，类别选 **集成 (Integration)**。
4. 搜索 **ROBAM ROKI** 并安装。
5. 重启 Home Assistant。

### 手动安装

1. 下载 release 的 `robam_roki.zip` 或源码包。
2. 把里面的 `custom_components/robam_roki` 放到 HA 配置目录的 `custom_components/robam_roki`（zip 解压到配置目录即可）。
3. 重启 Home Assistant。

## 快速开始

1. **设置 → 设备与服务 → 添加集成**，搜索 **ROBAM ROKI**。
2. 输入老板 / ROKI App 的登录手机号与密码。
3. 勾选要接入的设备，完成。集成会自动同步属性，加载阶段只读、绝不误启动油烟机。
4. 进入集成卡片上的**配置**按钮，可以看到 5 个入口：1 个「常规设置」和 4 个编号流程：

| 选项入口 | 用途 |
| :--- | :--- |
| **常规设置** | 档位列表、未知型号的档位数量、轮询间隔、实时推送、倒计时自动关机、是否允许未验证的控制 |
| **1. 学习新设备控制** | 被动记录官方 App 发往设备的命令，验证后变成 button 实体（见下） |
| **2. 生成草稿** | 把学到的动作写成 profile 草稿并自动放进 `profiles/`，可一键开启实验开关并重载 |
| **3. 导出贡献包** | 生成五节 .md（设备与匹配 / 验证清单 / profile / fixture / 如何贡献），用于贴 issue 或提 PR |
| **4. 清理草稿** | 勾选删除草稿、fixture、导出包；手写的 profile 不会被删 |

### 油烟机有哪些实体

| 平台 | 实体 | 说明 |
| :--- | :--- | :--- |
| fan | 排风 | 开关、百分比档位、档位预设 |
| select | 档位 | 关档 / 弱档 / 中档 / 强档 / 爆炒档 直选（关档即关机） |
| light | 灯光 | 照明灯开关 |
| number | 倒计时 | 0–240 分钟；到点由集成补发关机（可在选项关闭） |
| sensor | 工作状态 / 故障代码 | 关机 / 开机 / 延时关机；故障自检 |
| binary_sensor | 需要清洁 / 在线 | 清洁提醒、连通性诊断 |
| button | 学到的动作 | 学习模式生成的控制，点一下发送当初那一帧 |

## 给不支持的设备加控制

没有内置驱动的设备，也能自己把控制补上，全程不用写代码：

1. **只读接入**：先正常添加设备，确认云端能读到这台设备的属性（能看到属性实体即可）；完全读不到属性的设备不会加入，需要先排查接入问题。
2. **学习**：**配置 → 1. 学习新设备控制**，选设备、设时长（默认 300 秒），动作选「开始」；然后用官方 App 操作你要接入的功能（开关、模式、灯……）。学习最长 600 秒，**到时间会自动结束**，也可以回来手动提前结束。集成只记录 App 发往这台设备的命令，**不发送任何命令**。
3. **生成草稿**：回到菜单选 **2. 生成草稿**。草稿会直接写入 `<配置目录>/robam_roki/profiles/`（同名自动加 `-2`/`-3`）。确认页会显示草稿文件名和 controls 条数；完整路径与每个动作推测出来的名称在生成的 `draft-*.yaml` 里（调用 `robam_roki.draft_profile` 服务时会出现在持久通知中）。
4. **验证**：在确认页勾选「开启允许未验证的控制并重载」，学到的动作就会变成 button 实体；名称取草稿里推测出的 `name`（例如「开机」），在设备页里按设备筛选就能找到。逐个点一下，和官方 App 的效果对照。确认后把 profile 里对应条目的 `verified` 改成 `true`。若这个选项已经开启，确认页只会问是否立即重载。
5. **导出与反馈**：回到菜单选 **3. 导出贡献包**，它会生成一份 **Markdown**（`<配置目录>/robam_roki/exports/…md`，五节：设备与匹配、验证清单、profile、fixture、如何贡献）。把这份 .md 贴到 [新设备支持 issue](https://github.com/darkaccount/ha-robam-roki/issues/new?template=device_support.yml)，或直接提 PR。

细节（字段含义、合并规则、日志解读）见 [PROFILES.md](./PROFILES.md)；贡献流程与维护者工具见 [CONTRIBUTING.md](./CONTRIBUTING.md)。

## 常见问题

**实体显示「不可用 / unavailable」怎么办？**
集成只读云端状态，设备离线、账号掉线或云端缓存为空时实体会不可用。先确认官方 App 里能看到这台设备在线，再重载集成；登录过期会弹出重新验证流程，提示重新登录。

**倒计时实体有时不可用？**
倒计时只在油烟机运行（档位 > 0）时可用——关机状态下没有档位可带，命令会变成关机。倒计时由集成本地推算，轮询回报只作确认，所以显示可能比设备面板慢一两秒。

**为什么学到的动作默认看不到？**
学习结果一律标记为未验证（`verified: false`），默认不生成实体，避免误触发。打开选项「允许未验证的控制」后按钮才会出现，并带 `experimental: true` 属性；验证完成后把 profile 里的 `verified` 改成 `true` 再关掉这个选项。

**REST 设备学不到动作？**
学习模式抓的是 MQTT 帧。走 HTTPS 的 REST/SSE 设备没有可旁听的明文帧，学习会记录 0 个动作；这类设备目前只能只读接入，控制需要抓包证据，欢迎在 issue 里提供。

**升级后实体变成「恢复 / restored」？**
多半是 profile 匹配变了或某个平台不再生成实体。检查日志里的 `profiles:` 一行和「修复」里的 profile 提示；也可以先用服务 `export_profile` 导出现状再排查。

**多个草稿会不会打架？**
同一 dc/dt 的多份 `draft-*.yaml` 会互相竞争匹配，日志里会出现 `profile conflict`。用**选项 → 4. 清理草稿**勾选删除（默认只勾草稿），或只保留一份。

## 路线图与已知限制

### 为什么有些设备只有只读

| 层 | 原因 |
| :--- | :--- |
| **通道** | MQTT 设备的命令是明文帧，可以旁听学习；**REST / SSE 设备**的控制是 HTTPS 写请求，没有可旁听的明文，学习会记录 0 个动作 |
| **能力** | 配置文件支持 `kind: property`（REST 属性写）与 `kind: invoke`（云函数），但自定义 profile 里声明的 `property` 和带参数的 `invoke` 暂时不生成 button 实体。内置油烟机驱动的开关、档位、灯光、倒计时已经通过这两类命令驱动 fan / light / number / select 实体 |
| **原则** | 只读先行是硬规则：新品类默认只读，避免发错命令让设备真的动作；开启控制必须有 `verified: true`，或用户显式打开「允许未验证的控制」 |

### 用户能自己补上控制的条件

同时满足这三条，就可以用学习模式自己写出可用的控制：

1. 命令以 **MQTT 明文**出现（能被学习模式或 CLI 采集旁听到）；
2. 你能在官方 App 里**触发**这个命令；
3. 设备对该命令**确实有响应**（能观察到属性变化）。

不满足时，只能先只读接入。

### TODO（缺设备或证据，暂时不做）

- **自定义 profile 的控制实体**：为 profile 里声明的 `property` 控制与带参数的 `invoke` 补上实体形态。REST 属性写与带参云函数调用的底层通道已经实现（内置油烟机驱动在用），缺的是给任意 profile 声明生成实体；这需要一台真实的 REST 设备 + 官方 App 的请求样本来验证。
- **更多品类的控制**：烤箱 / 洗碗机 / 净水器等的控制命令，同样需要真机证据；目前这些品类只有只读遥测。
- **品牌图标**、更多语种的服务描述（`services.yaml` 目前只有中文描述，英文已由 translations 提供）：纯展示项，优先级低。

如果你有上面缺的设备，欢迎按 [CONTRIBUTING.md](./CONTRIBUTING.md) 提供只读证据或命令样本。

## 进阶：命令行（可选）

需要一个 Home Assistant 以外的 Python 环境。**不需要装 HA**：整条主链只跟云端说话。

```bash
pip install -r tools/requirements.txt
python tools/roki_cli.py        # 不带参数：进入交互菜单
```

主链是四步，菜单按这个顺序摆好：

1. **读设备信息** —— 登录后拿设备列表与属性，全程只读。
2. **生成配置**（菜单 3）—— 用属性直接生成 `profiles/<dc>-<dt>.yaml` 与 `fixtures/<dc>-<dt>.json`，自动继承内置驱动（`extends: python:<driver>`）并跳过驱动已覆盖的键。只读设备到这一步就用完了。
3. **采集命令并合并**（菜单 4）—— 在官方 App 里操作设备，回来按回车结束（120 秒上限）。采到的命令帧会**自动合并**进已有配置：按 command + `body_hex` 去重，保留 sensors、注释与手工改动，只追加新的 `action_N`；没有配置时直接生成一份新的。
4. **导出贡献包**（菜单 5）—— 五节 `.md`，整份贴 issue，或交给 `tools/promote_profile.py` 落地。

设备控制放在菜单 7 的二级菜单，每条命令发送前都显示「将向 {设备} 发送：…」，输入 `y` 才真的发；`invoke` / `setprop` 这类调试命令不进菜单。诊断与档位表在菜单 6 的二级菜单里。

凭据可用启动参数 `--phone/--password` 或环境变量 `ROKI_PHONE/ROKI_PASSWORD`；都没有时，第一次需要联网的任务会提示输入（密码不回显）。凭据只在本次会话里复用，**不写任何本地文件**。设备列表按编号选，本次会话记住上次的选择，下次回车沿用。

自动化（脚本 / CI）用子命令，行为与菜单一致：

| 子命令 | 作用 |
| :--- | :--- |
| `config init <GUID>` | 从设备属性生成配置 + fixture（只读，绝不发命令）；同名文件已存在会询问，非交互运行时追加 `-2` |
| `collect --device <GUID>` | 被动采集证据包，同时记录官方 App 发出的命令帧（只发布只读状态查询，绝不发控制命令） |
| `draft <bundle.json> [--merge profiles/<dc>-<dt>.yaml]` | 生成草稿；`--merge` 把采集结果合并进已有配置（保留 sensors / 注释 / 手工改动，按 command + `body_hex` 去重；目标不存在时直接新建） |
| `export <bundle.json>` | 生成五节贡献包 `.md`（与 HA 的 `export_profile` 同结构）；导出前问一次「这些控制是否已在真机上逐个验证过？」，默认 N |
| `login` / `devices` / `info` | 查看账号、设备与属性 |
| `levels` / `watch` | 只读查看档位梯子与设备上报 |
| `power` / `level` / `light` / `timing` | 发送控制命令（调试用，需自备 GUID） |
| `poll` / `invoke` / `setprop` | 只读状态查询 / 云函数调用 / 属性写（调试用，需自备 GUID） |
| `mqttcheck` / `dump` | MQTT 连通性诊断 / 脱敏诊断 JSON |

`--help` 会列出全部子命令及参数；菜单里输入 `?`（或 `？`、`h`、`help`）显示的是同一份完整命令行帮助，不是上面这张常用子命令表。

完整命令、证据格式与脱敏规则见 [PROFILES.md](./PROFILES.md)。

## 参与贡献

- 想让自己设备的控制被官方支持：按上面「给不支持的设备加控制」走一遍，把导出的 .md 贴到 issue 或 PR 即可。
- 代码 / 文档贡献：先看 [CONTRIBUTING.md](./CONTRIBUTING.md)，提交前请确保 `pytest tests/` 全绿（CI 跑的是同一套测试）。
- 安全红线：不主动探测设备、不为了取证发送控制命令；提交前确认没有 secrets、没有真实手机号 / token / App GUID。
- 自动生成的 fixture 属性与采集帧体已经脱敏；导出包还会原样带上你手写的 profile 全文、设备名和配置目录路径，贴到 issue 前请自己看一眼，确认里面没有设备 GUID、手机号、token 或 App GUID。
